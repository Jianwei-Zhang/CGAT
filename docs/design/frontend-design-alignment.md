## 零、实施边界与证据基线

### 0.1 范围分层

| 分类 | 本轮处理方式 | 不允许顺带改变的内容 |
| :--- | :--- | :--- |
| V：视觉基础 | Tokens、字体、图标、按钮、表格、弹窗及图形外观统一 | 业务含义、坐标、标记位置、导出数据 |
| I：交互与布局 | 项目入口、导航、筛选、工具条、编辑反馈和 Studio 布局分阶段迁移 | 导入分类、取消/清理、持久化边界、现有历史栈语义 |
| F：独立新增功能 | 统一历史事务、新科研指标、产物摘要/压缩包、SVG、Focus Beam，单独定义契约后实施 | 不得混入样式提交，不作为基础 UI 升级的隐含交付 |

- 保持现有 JavaScript 模块、store、事件绑定、服务/Tauri 边界；本轮不同时迁移 React/Vue/Tailwind 等框架。“Slate”仅指调色参考。
- 不升级数据库/工程格式，不重算旧科研结果，不覆盖用户原工程；基线采集使用工程副本。
- 保留四条核心路径：项目导入/管理、Project Preview、Assembly、Project Export，以及它们的设置、进度、错误、空态和恢复流程。
- UI 标签可改善，持久化字段名、来源身份、导出列及调用接口不得为文案统一而改名。

### 0.3 前端工程师落地调优决策（Engineering Refinements）

在对照现有 12 个样式模块与 1,530 项单元/架构测试后，为确保“**简洁、美观、流程、专业**”四个目标高质量落地且零回归，做出以下关键工程收敛：

1. **做减法而非堆砌装饰（Concise by Subtraction）**：
   - **导航栏不加强制步骤序号**：科研人员在 `预览 ↔ 组装 ↔ 导出` 之间高频往返，导航栏重塑为现代**分段控制器（Segmented Pill Bar）**，通过浅色轨道槽（`#eef2f6`）与白色悬浮激活态建立流程秩序，不强加 `1./2./3./4.` 伪向导前缀。
   - **工程选择器保持原生零延迟**：解除 `#session-workspace-select` 硬编码 `96px` 的局促限制，扩展为自适应宽度（`min(220px, 26vw)`）并优化文本截断与边框质感，保留原生 `<select>` 极速切换与键盘可访问性，不增加冗余浮层。
   - **守护外层方正、内层圆角的架构契约**：维持外层工作台 `.panel` 直角（`border-radius: 0`）贴合视口边界、内层全部卡片共享 `--card-radius: 6px` 的架构不变式（与 `stylesheet-architecture.test.mjs` 严格对齐）。
2. **保留已校准的低饱和科研轨道配色（Calibrated Bio-Palette）**：
   - 主组装（`#d2dfef` / `#6d85a1` / `#243a54`）、辅助组装（`#e7dec4` / `#8a7551` / `#5c492a`）与参考基因组（`#cfcfcf` / `#8e8e8e` / `#4f4f4f`）已在 `de32158` 与 `028bf8a` 中完成跨视图及无头导出对齐。低饱和度底色能避免长时间阅片视觉疲劳，并确保端粒、着丝粒、LGZ 弧线与标签文字清晰可读。本轮**保留该套轨道语义色**，重点升级外围工作台、按钮、表单、表格与浮层的现代 Slate 质感。
3. **统一全局 Design Tokens 与控件质感（Cohesive Slate Tokens）**：
   - 在 `base.css` 中建立统一的背景表面（`--surface-app`、`--surface-panel`、`--surface-subtle`、`--surface-elevated`）、边框（`--border-subtle`、`--border-default`、`--border-strong`）、阴影与焦点环 token；
   - 彻底淘汰 `shared-components.css`、`shell.css`、`assembly.css`、`final-path.css` 等模块中的旧式灰色线性渐变（`linear-gradient(#fbfbfb, #dfdfdf)`），仅保留信息语义渐变（导入进度动画、Gap 斜纹等）。

## 一、现状诊断：三大设计方言与视觉痛点

对当前样式代码（`base.css`、`layout.css`、`assembly.css`、`importer.css`、`subview.css`、`final-path.css` 等）的审视表明，系统中并存着三个不同时期的设计方言：

1. **Windows 经典灰色渐变方言（Legacy Gray）**：
   - 依赖大量灰底渐变：`linear-gradient(#fafafa, #e6e6e6)`、`linear-gradient(#fbfbfb, #dfdfdf)`。
   - 硬质边框：`#9f9f9f`、`#b9b9b9`、`#c2c2c2`；底色采用厚重冷灰 `#e6e6e6`。
   - 直角 `border-radius: 0`（`.panel`）与卡片圆角 `var(--card-radius)（当前 6px）` 混杂，视觉接缝生硬。
   - 按钮采用 ASCII/Unicode 纯符号（`▾`, `▴`, `↺`, `X`, `⚙`, `>`），缺乏现代桌面图标统一规范。
2. **现代 Slate/Tailwind 质感方言（Modern Slate）**：
   - 部分近期模块（如导入进度弹窗 `.importer-import-progress-dialog`、视口导航 `.assembly-view-navigation`）已引入现代设计语言：`#0f172a`、`#1f2937`、`#64748b`、`#cbd5e1`，配合 `backdrop-filter: blur(2px)` 和平滑阴影。
   - 新旧模块在同一视图中并存时，产生明显的视觉断层。
3. **高密度生物数据可视化方言（Domain Track Canvas/SVG）**：
   - Canvas、SVG 和 HTML 轨道仍需统一外观，但 Main/Local、Final Path 与项目导出已具备共享 Contig role 调色入口，应在现有契约上扩展，而非另建一套颜色映射。标签溢出与缩放视差须通过真实用例确认。
   - 重点改进目标是**长页面中跨面板往返**：记录主视图、局部视图与 Final Path 之间的操作路径和滚动距离，再验证 Studio 布局是否缩短往返；不以隐藏有效内容换取“无滚动”。

## 三、逐页面、逐面板、逐对象审视与重塑

### 页面一：项目入口与工程库（Project Importer & Library）

> **流程定位**：科研人员的第一站。“已有工程秒级进入”、“新建导入一目了然”、“数据状态严谨透明”。

#### 面板 1.1：左侧项目历史库面板 (`.project-recents`)
*   **对象 1：导入/打开主按钮 (`#project-import-button`, `#project-open-button`)**
    *   *现状*：两个按钮并列，空库时 import 变亮，非空时两者都退化为浅灰 Ghost。
    *   *对齐规范*：空库或无就绪工程时，“导入交付包（Import Bundle）”作为主要操作，“打开本地目录（Open Folder）”作为次要操作；已有就绪工程时主操作转为进入组装，导入降为次要操作。
*   **对象 2：库头部管理控制 (`#validate-history-button`, `#delete-failed-history-button`)**
    *   *现状*：“校验记录”、“删除失效记录”常驻显示在标题栏，字数长，容易带来非必要的使用焦虑。
    *   *对齐规范*：折叠为右侧低频更多菜单（`...`），仅在检测到失效路径时以温和的小徽章（Badge）提示，避免无关管理功能抢占核心工作流。
*   **对象 3：历史项目行卡片 (`.project-recent-row`)**
    *   *现状*：单行排列，左侧名字，右侧紧挨 3 个方形小图标（追加包、复制、删除），失效行仅有淡红框。
    *   *对齐规范*：重构为两行式现代列表项：
        *   第一行：状态图标与文字（当前/可用/失效）+ 工程名称；仅在数据确有来源时显示上次打开时间，不伪造时间戳；
        *   第二行：展示末尾两级路径（等宽灰色小字，Tooltip 显示全路径）；
        *   右侧操作列在 Hover 或 `focus-within` 时显现；键盘聚焦时不得成为不可见按钮，触控/无悬停设备保持可见；删除按钮采用危险操作语义。

#### 面板 1.2：右侧当前工程详情面板 (`.project-current`, `workspace-page.js`)
*   **对象 1：项目标题与重命名表单 (`.project-title-row`)**
    *   *现状*：原生 input 动态计算字符数，重命名时由于宽度的重算会有细微晃动。
    *   *对齐规范*：重塑为原地无缝编辑：双击标题或点击可键盘访问的铅笔按钮进入输入框（Focus Ring），回车确认，Esc 取消；中文输入法候选确认不触发提交，失败时保留草稿。
*   **对象 2：核心推进行动点——进入组装按钮 (`#initializer-enter-assembly-button`)**
    *   *现状*：放置在右上角普通位置，容易被误以为是普通配置项。
    *   *对齐规范*：提升为该面板的**核心行动召唤（Hero CTA）**，位于工程标题下方或数据集底部，呈现清晰主按钮：“进入组装工作台 →”；项目就绪时作为本页唯一主操作，未就绪时主操作为导入。`Ctrl/Cmd + Enter` 仅在快捷键任务落实后展示。
*   **对象 3：数据集目录表格 (`project-catalog-view.js`)**
    *   *现状*：表格灰边框重，数据角色仅是纯文本，数值没有右对齐。
    *   *对齐规范*：
        *   数据角色（Primary / Auxiliary / Reference）统一为语义标签胶囊（Tag Pill）；
        *   序列数与总长度数值必须**靠右对齐**并启用等宽数字（`tabular-nums`），千分位格式化；
        *   详情弹窗内增加路径复制；“打开所在目录”仅在现有宿主能力允许时启用，不静默扩大 Tauri 权限或把文件夹打开实现为任意 shell 执行。

#### 面板 1.3：导入与复制弹窗 (`.project-import-dialog`, `.project-copy-form`)
*   **对象 1：来源单选切换 (ZIP vs 已解压目录)**
    *   *现状*：原生单选框，排布松散。
    *   *对齐规范*：升级为并排的现代卡片选择器（Visual Segment Card），直观显示两者的差异说明。
*   **对象 2：路径与浏览按钮组合 (`.inline-input`)**
    *   *现状*：输入框和按钮拼接处有双重边框感。
    *   *对齐规范*：将“选择目录”图标嵌入 Input 内部右侧（Suffix Action），减少界面接缝。

### 页面二：全景预览（Project Preview）

> **流程定位**：工程级组成与来源概览，查看当前 Final Path、Gap 与方向并进入相应染色体。颜色或箭头不等于自动判定倒位、易位等生物学异常。

#### 面板 2.1：页面头部与全局筛选工具条 (`.project-preview-heading`)
*   **对象 1：标题区**：压缩标题空间，优先展示已有且口径明确的染色体数与长度；多单倍型长度分开标识。“待处理区域”须先定义数据来源，不能直接把 `unresolvedCount` 当成生物学异常数。
*   **对象 2：全局过滤与视图工具组**（新增规划）：
    *   支持染色体快速检索输入框（如输入 `chr01` 即刻过滤）；
    *   排序切换：先支持按名称/已明确口径的路径长度排序；Gap 数排序须标明按哪条路径计数，不命名为“异常”排序；
    *   显示密度切换：紧凑模式（仅 Final Path 条带）与完整模式（含各数据源轨迹）。

#### 面板 2.2：染色体多轨概览卡片 (`.project-preview-card`)

### 4.1 视觉栅格与层次对齐 (Visual & Surface Elevation)

全应用严格实行 4 级表面分层，淘汰旧版灰底与生硬直角：

| 层级 | 语义与应用场景 | 背景色 (Light Mode) | 边框 (Border) | 阴影 (Shadow) | 圆角规范 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Layer 0** | 应用底层背景 (`body`, `.desktop-shell`) | `#f1f5f9` (`--surface-app`) | 无 | 无 | 无 |
| **Layer 1** | 顶层工作台容器 (`.panel`) / 业务卡片 (`.card`) | `#ffffff` (`--surface-panel`) | `1px solid #dbe3ec` (`--border-subtle`) | `0 1px 3px rgba(15,23,42,0.05)` | `.panel` 保持 `0`；`.card` 统一 `--card-radius: 6px` |
| **Layer 2** | 内嵌视窗画布（轨道区、表格槽、次级容器）| `#f8fafc` (`--surface-subtle`) | `1px solid #cbd5e1` (`--border-default`) | `inset 0 1px 2px rgba(15,23,42,0.03)` | `--card-radius: 6px` / `4px` |
| **Layer 3** | 下拉菜单、Tooltip、模态弹窗、浮动工具窗 | `#ffffff` (`--surface-elevated`) | `1px solid #cbd5e1` (`--border-default`) | `0 12px 32px -4px rgba(15,23,42,0.14)` | 菜单/提示 `6px`；模态框 `var(--card-radius)` / `12px` |

### 4.2 生物语义色彩字典对齐 (Biological Color Semantics)

在专业生命科学工具中，同一视觉编码必须具有稳定含义，但 role、dataset 身份、haplotype、方向与证据类型是不同维度，不能互相覆盖。已校准的轨道核心 token 保持如下：

| 实体角色 | 语义色彩 | 填充色 (Fill) | 描边色 (Stroke) | 文本/前景 (Text) | 设计说明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **主组装 (Primary)** | 科研钢蓝 | `#d2dfef` (`--ctg-primary-fill`) | `#6d85a1` (`--ctg-primary-stroke`) | `#243a54` (`--ctg-primary-text`) | 低饱和主组装基底，长时间阅片不刺眼 |
| **辅助组装 (Auxiliary/Companion)** | 温暖沙褐 | `#e7dec4` (`--ctg-companion-fill`) | `#8a7551` (`--ctg-companion-stroke`) | `#5c492a` (`--ctg-companion-text`) | 补缺证据数据，与主组装钢蓝温和互补 |
| **参考基因组 (Reference)** | 中性基准灰 | `#cfcfcf` (`--ctg-ref-fill`) | `#8e8e8e` (`--ctg-ref-stroke`) | `#4f4f4f` (`--ctg-ref-text`) | 对比基准坐标，不喧宾夺主 |
| **轨道选中高亮 (Active)** | 清透天蓝 | `#b9d0ea` | `#2e567f` | `#1e3a5f` | 瞬态交互高亮，保持与 Subview 一致 |
| **Gap 未知区** | 警示斜条纹 | 灰白斜纹相间 | `#94a3b8` / 半透明深灰 | `#64748b` / `#766239` | 严禁显示为空白，传达序列未知区间 |
| **端粒 / 着丝粒** | 真实区间标记 | 按既有 SVG 标记色 | `#ffffff` | — | 严格按实际 `ctgStart/ctgEnd` 区间渲染 |

- 上表是目标候选色，不改变 role 解析规则。来源 dataset 的稳定标识/图例独立保留；Hap1/Hap2 用标签、边线等辅助编码，不覆盖来源色；至少提供非颜色区分方式。
- Main、Subview、Final Path、Preview、导出图须使用明确的对应图例。更新现有 CSS token 时同步 `contig-colors.js` 无 DOM fallback；不要全局替换十六进制颜色。
- 仅清除装饰性的灰色渐变；Gap 斜纹、网格、进度动画等有信息用途的样式不按 `linear-gradient` 字样批量删除。

### 4.3 交互行为与契约对齐 (Interaction Contracts)

1. **按钮层级与唯一性原则**：
   - 每个当前操作上下文**只突出 1 个 Primary 主动作**，如“进入组装流程”、“导入交付包”、“导出全部文件”；模态框可有自身主动作，其余次要操作一律采用 Secondary 描边或 Ghost 纯文本/图标。
2. **基因组坐标与数值展示契约**：
   - 基因组长度、坐标（bp, kb, Mb）采用等宽数字；下例右对齐仅用于数值表格列，SVG 刻度/轨道标签仍按几何锚点定位：
     ```css
     font-variant-numeric: tabular-nums;
     text-align: right;
     ```
   - 严禁不同行的数据因为字符宽度不同产生水平抖动。
3. **数据安全与无损操作历史**：
   - 基础升级只连接现有主视图/Subview 历史，明确标注操作范围、禁用原因和当前染色体；不承诺 Final Path 已进入同一撤销栈。
   - 全局跨域撤销是 F01，需要操作归属、事务边界、持久化回滚、失败恢复与重做失效规则。不得把操作日志当作可恢复快照。
   - 快捷键按焦点与当前操作域分发，输入框保留原生文本撤销，IME 组合输入优先；支持 Windows/Linux Ctrl 与 macOS Cmd，未实现的快捷键不显示。
4. **坐标与科研数据不变式**：
   - 保持每个既有接口的坐标基准和闭/开区间约定，所有转换集中在原模型入口；显示四舍五入不得写回数据。
   - 保留来源 dataset/Contig ID、切分与反向映射、跨染色体采用、多路径和 Ref 语义；不得用名称或颜色代替身份。
   - 区分显式 Gap 与来源内部 N；不通过最小绘制宽度改变真实 bp 长度；Preview 与 Assembly/导出使用同一来源契约。
5. **异步、可访问与本地化**：
   - 所有组件覆盖空态、加载、禁用、失败、取消中、完成；取消请求与清理完成分离，关闭浮层不能放开冲突任务。
   - Tab 顺序、focus-visible、菜单键盘操作、弹窗焦点恢复、图标可访问名称与 reduced-motion 一并实现；不只依赖 Hover、颜色或双击。
   - 保留中英文、界面字号 12/14/16/18、图中文字跟随/独立 10/12/14/16 设置，布局/命中区域与文字一起变化。

### 4.4 空间布局与流程心智解耦 (Studio Layout Paradigm)

目标是减少主视图、局部编辑与最终路径之间的跨屏往返，而不是承诺所有数据都无需滚动。

> **架构现状与收敛说明**：当前源码（`render-tracks.js` 与 `assembly-view-layout.test.mjs`、`subview-toolbar.test.mjs`）已将顶部序列池默认折叠为单行（`membersCardCollapsed !== false`），并将 `Main Track` 与 `Local View (Subview)` 合并进同一个 `.assembly-main-view.card` 容器（通过 1px 分隔线紧邻排布），下方紧接 `.final-path-card`。该**一体化纵向工作台卡片（Unified Stacked Studio Card）**在不引入隐藏 Tab 零宽视口风险的前提下，已显著缩短了主视图、局部视图与 Final Path 之间的视觉跨度。下文可拖动分栏/Tab Dock（W01–W03）保留为后续可选增强阶段。

```text
┌───────────────────────────────────────────────────────────┐
│ App Nav / 项目上下文 / 设置                                │
├───────────────────────────────────────────────────────────┤
│ 染色体选择 / 主视图工具条 / 当前作用域历史                  │
├───────────────────────────────────────────────────────────┤
│ Main Track：独立视口，共享几何与滚动同步                   │
├════════════════ 可拖动分隔条 ══════════════════════════════┤
│ [Subview] [Final Path] [候选池]  [固定对照] [收起]          │
│ 当前面板；空间足够时可固定 Subview + Final Path 对照        │
└───────────────────────────────────────────────────────────┘
```

- 初始主区/下区比例以可用工作区约 65/35 为试验值，不包含导航和工具条；最小高度、窄窗降级与字号影响须在基线中确定。允许面板内滚动，禁止强行裁剪数据。
- Tab 内容默认保留已挂载节点/业务状态，隐藏面板不参与焦点导航；不以重复 `innerHTML/outerHTML` 切换 Tab。若必须重建，须提供完整恢复契约并通过状态回归。
- 保留横向滚动、bp 视口、缩放、选区、候选、未提交输入、历史及异步任务；拖拽进行中不得切换/销毁承载面板，取消拖拽要恢复状态。
- 隐藏面板不得以零宽尺寸覆盖有效视口；重新显示/拖动分隔条后重测 Canvas/SVG 和导航器，屏蔽布局恢复产生的伪用户滚动。
- 布局偏好使用版本化、可回退的应用设置，不混入科学工程数据；路由缓存须区分布局版本，语言/字号/工程切换不能复用不兼容 DOM。
- 先以用户可选布局试行，旧布局保持可切回；完成原生体验与数据不变验收后再决定是否切换默认。Focus Beam 不在此阶段强制实施。

## 五、分阶段落地演进路线（Implementation Roadmap）

> 原则：先冻结不变量，再改视觉，再改状态敏感布局；新增业务能力独立交付。不将“全前端升级”解释为一次性替换所有渲染代码。

| 阶段 | 任务 | 交付及退出条件 |
| :--- | :--- | :--- |
| Phase 0：分支与基线 | B01–B02 | 在用户启动实施后创建升级分支；记录源码 SHA、工程副本、现有问题、数据/性能基线和回退点 |
| Phase 1：视觉与公共组件 | V01–V04 | Tokens、图标/基础控件、浮层、语义色收敛；不改坐标、历史或业务数据 |
| Phase 2：页面与交互 | S01、P01–P04、A01–A04 | Shell/设置、项目库/导入、Preview、Export、Assembly 各面板逐个验收；仍保持原布局可用 |
| Phase 3：Studio 工作台 | W01–W03 | 版本化布局偏好、稳定 Tab/固定对照、尺寸/缓存/状态恢复；旧布局仍可切回 |
| Phase 4：整体验收 | Q01–Q02 | 快捷键/焦点/双语、完整流程、最终 SHA 的 CI 和原生验收；满足门槛后才切换默认 |
| 独立功能批次 | F01–F05 | 全局事务历史、新指标、摘要/压缩包、SVG、Focus Beam；逐项确认契约后实施，不阻塞基础升级 |

每个任务的文件入口、依赖、验收与提交边界见[任务清单](frontend-upgrade-tasks.md)。依赖关系不授权并行 agent；按仓库规则顺序实施。

## 六、验收与回退

### 6.1 数据与交互基线

至少覆盖无项目/空库、正常/失效工程、ZIP/目录/拖放导入、普通/多单倍型/含 Ref 路径、重叠采用片段、切分/反向/跨染色体片段、显式 Gap/内部 N、LGZ 有结果/无结果、长路径/长名称和大工程。

- 对同一工程副本比较坐标、方向、来源 ID、Final Path 每段及每染色体长度/序列摘要、FASTA 内容、TSV 字段/记录与日志语义。时间戳/输出目录等非确定字段单列，不用宽泛归一化掩盖数据变化。
- PNG 等视觉产物允许因设计改变而变化，但必须另验标签、图例、标记与几何；不能以图片 hash 不同推断科研数据不同。
- 验证非零横向位置下切换 LGZ、Tab、路由、语言、字号与窗口尺寸；同尺寸切换应保留像素偏移，变尺寸时保留 bp 视口/选区，且不把恢复事件写成用户操作。
- 导入取消后仍禁止冲突操作直到清理完成；失败历史不能阻断新导入；复制、重命名、保存失败要保留可恢复信息。

### 6.2 验证层级与环境

1. **每个任务**：先源代码/diff 和定向自动测试；纯文档变更只检查引用、任务依赖、Git 规则与差异，不运行应用测试。
2. **阶段出口**：Windows 主机 `node.exe/npm.cmd` 执行前端测试/生产构建；构建后按仓库要求清理生成的 `dist/`。禁止 WSL Node/npm 使用共享 Windows `node_modules`。涉及 Tauri 时按项目规则在 Windows 验证 Rust。
3. **CI**：以 `.github/workflows/quality.yml` 为准。当前仅 master push 自动触发；功能分支需 PR 或明确手动触发。记录最终 head SHA 对应的 `Windows app`、`Linux server` 结果，不能拿旧提交成功替代。
4. **原生验收**：布局、拖拽、焦点与 DPI 不能仅靠字符串测试证明。安排 Windows/macOS 原生应用验收，记录平台/WebView、窗口、字号与数据；至少覆盖 1280×720、1920×1080、Windows 100%/150%/200% 缩放及 macOS Retina。缺少的平台标记未验收，不宣称已通过。
5. **性能**：在相同工程、设备、窗口、字号与冷/热缓存条件下测量页面切换、图层切换、拖拽与布局调整；B02 先确定预算，后续不临时放宽。记录耗时分位数、长任务/卡顿与内存/节点数，禁止用删减校验或数据换速度。

遵守轻量优先：不自动启动浏览器或安装浏览器检查环境；需要额外浏览器验证时先说明具体无法由轻量检查确认的问题。源码/自动测试、CI、原生视觉验收、用户最终确认分别记录。

### 6.3 分支、提交与回退

- 应用升级使用新分支（建议 `feat/frontend-modernization`），从实施时确认的干净 master/upstream 基线创建；本次文档提交不代表该分支已创建。不要为切分支丢弃或自动 stash 他人改动。
- 文档须受版本控制：仅放行本规范与任务清单，保持其余本地 `docs/` 源码/工具链忽略规则，不使用全目录强制添加。
- 每次只提交当前任务及其测试，记录“任务 ID / 变更边界 / 证据 / 未验收项 / 回退方式”；基础样式、布局和新增业务不得混成一个提交。
- 单任务回退优先恢复对应提交；Studio 可关闭新布局，旧工程不依赖新布局配置。默认切换与旧布局删除必须分开，不能在没有回退窗口时同时删除旧路径。
- 最终合并前检查全部 B/V/S/P/A/W/Q 任务与验收证据；F 类未实施须明确列为后续范围，不写成“整个计划已全部完成”。
