## English

### Server

- Improve ordinary-query throughput in initial reference mapping. New workspaces default to `-K 1G`; use `-K 500M` if memory is insufficient. This controls query batch size, not a RAM limit, and larger batches can use more memory. Existing workspaces keep their saved settings.
- In mixed ordinary/long-query tasks, reuse existing original reference-index partitions and map the ordinary group in parallel when the assigned CPU and verifiable memory budget permit. Otherwise retain native execution. Pure ordinary tasks keep the native direct path, ordinary query records are not split, and result merging performs fewer file operations while preserving output bytes and order. Controlled comparisons passed; speedups depend on the data and do not establish acceptance of the customer's original wheat assembly.
- Add explicit `-f 0.01` / `--minimap-filter 0.01` for faster, more aggressive seed filtering in initial reference mapping. It may change alignments and is never enabled automatically; use a new output directory when changing this setting. The default preset filtering remains unchanged.
- Verify content instead of aborting solely because input or private-cache `ctime` changed. Reuse verified digests within the current process while file metadata remains stable, avoiding repeated full scans of large unchanged inputs and indexes; actual content changes and damaged/replaced caches still stop unsafe reuse.
- Reuse completed ordinary reference mapping across the reviewed runtime updates when original inputs, mapper, indexes and successful PAF evidence pass validation. Resume validated completed partitions without remapping them; do not reuse failed partial PAF or skip long queries. Formal recovery no longer inherits the standalone diagnostic six-hour subprocess limit.
- Allow execution-resource budgets, including threads and the initial-reference query batch size, to be adjusted when resuming a stopped compatible workspace. Keep validated checkpoints and immutable preparation records; direct `run_all.sh` resumes use the saved budgets, and running processes are not resized in place.
- Keep startup updates noninteractive and routine offline messages concise. Prepared runtimes can align from their verified bound installation without another download; detailed diagnostics remain available. Offline checks do not establish online freshness, and damaged local tools still stop execution.

### App

- This Server-only maintenance refresh does not rebuild or replace the App installers; the v2.0.17 App changes below remain unchanged.
- Improve large-project responsiveness with lightweight Overview reads, visible-chromosome Preview rendering, and staged Assembly loading so Main View can become ready before contig details and Local View evidence.
- Reduce work during full-range contig drags by reusing the existing graph, while preserving labels, rulers, alignment geometry and dark-theme colors.
- Restore the correct Local View pairwise evidence after chromosome switches, and preserve intentional spacing when removing local contigs.
- Clarify auxiliary full-contig length and alignment filters. Keep parameter explanations on labels and settings icons instead of numeric inputs, and show name-completion tooltips only when needed.
- Improve Overview badges and Final Path selection outlines, and show the App version in the native window title.

- macOS: Intel and Apple Silicon (ARM64) installers.

### macOS first launch

This guidance applies to both Intel and Apple Silicon (ARM64) builds.

The macOS apps are ad-hoc signed but not Apple-notarized. Drag `GPM.app` to `/Applications` before opening it. If macOS blocks the first launch, open **System Settings -> Privacy & Security** and choose **Open Anyway**. If that control is unavailable, run the following command only for the app downloaded from this official Release:

```bash
xattr -dr com.apple.quarantine /Applications/GPM.app
```

## 中文

### Server

- 提高初始参考比对的普通 query 吞吐。新工作区默认 `-K 1G`，内存不足时可尝试 `-K 500M`。该参数控制 query 批大小，不是内存上限；扩大批次可能增加内存占用。已有工作区保留已保存的设置。
- 普通与超长 query 混合任务复用已有的原参考索引分区，在分配的 CPU 与可核实内存预算允许时并行处理普通组，否则保留原生执行。纯普通任务仍原生直出，不拆分普通 query 记录；结果合并减少文件操作，保留输出原始字节和顺序。受控对照已通过，但提速依赖数据，不代表客户原始小麦组装已完成验收。
- 初始参考比对新增显式 `-f 0.01` / `--minimap-filter 0.01` 高速选项，采用更积极的种子过滤，可能改变比对结果，不会自动开启；更改此设置时须使用新的输出目录。默认仍保留预设筛选策略。
- 仅输入或私有缓存的 `ctime` 变化时改为核对内容，不再直接终止；在本次进程内、文件属性稳定期间复用已验证摘要，避免反复全量扫描未变的大输入和索引。实际内容变化、缓存损坏或替换仍会阻止不安全复用。
- 本次已审查的运行时更新可在原始输入、比对工具、索引和成功 PAF 证据核验通过后复用已完成的普通参考比对，并保留已核验的完成分区，不重复映射；不复用失败的部分 PAF，不跳过超长 query。正式恢复任务不再继承独立诊断工具的六小时子进程上限。
- 兼容的已准备工作区停止后，可调整线程和初始参考 query 批大小等执行资源预算再续跑；保留已校验的检查点和不可变准备记录。直接通过 `run_all.sh` 续跑时沿用已保存的预算，不会原地调整正在运行的进程。
- 启动更新无需交互，离线常规提示保持简短；项目运行库可从已绑定、校验通过的安装同步，无需再次下载，详细诊断保留用于排障。离线检查不代表已确认线上最新版本，本地工具损坏时仍会停止运行。

### App

- 本次仅维护 Server，不重建或替换 App 安装包；以下 v2.0.17 App 更新保持不变。
- 通过轻量概览读取、按可见染色体渲染预览和装配页分阶段加载，改善大项目响应；Main View 可先于 Contig 详情与 Local View 证据就绪。
- 全范围拖动 Contig 时复用现有图形，减少重复计算，同时保留标签、标尺、比对几何和深色主题配色。
- 切换染色体后恢复正确的 Local View 成对比对证据；移除局部 Contig 时保留有意设置的间距。
- 明确辅助完整 Contig 长度与比对筛选的含义。参数解释只在标签和设置图标上显示，不再由数值输入区域触发；名称补全提示仅在需要时显示。
- 改进概览徽标与 Final Path 选中轮廓，并在原生窗口标题中显示 App 版本。
