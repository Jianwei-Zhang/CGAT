# 执行前分流：实现边界与重复计算清单

## 已确认的目标

不再以“原输入先崩溃”为入口。对于 10 条输入中有 1 条超长的情况，普通
9 条完整地走原生比对，超长 1 条直接特殊处理。不能通过预先切开所有序列
或把窗口 PAF 简单拼接来声称兼容。用户仍只使用原 run.sh/sbatch，无新配置。

本文件及新增模块是**隔离实验，不是正式 Server 切换或 Release 发布**。
本阶段复用已经冻结、逐文件校验的分支恢复运行时；不会改动安装的 minimap2。
旧的断言恢复分支尚未合入正式 Server，新分流也尚未接入正式结果发布门禁。

## 已实现：一次规划与一次分组准备

`proactive_reference_plan.py`：

1. 一次有界流式读取，同时计算输入字节 SHA-256、序列长度、原顺序、完整记录
   范围和逐记录 SHA-256；不额外全文件读取来计算这些哈希。
2. 支持普通 FASTA 和 gzip 流。gzip 的输入身份按压缩字节计算，记录范围按解压
   字节计算；不靠扩展名或未经校验的 `.fai` 推测长度。
3. 全普通输入：原文件直接复用，不制作标准化 FASTA、不拆记录、不建立额外
   预处理索引。预扫描自身仍是一遍新增 I/O，不能声称普通任务耗时完全不变。
4. 混合输入：统一再读取一次，输出一个普通记录批次及各超长记录。不是每发现
   一条超长序列就重扫整个输入。最多同时打开普通输出和当前超长输出两个句柄。
5. 保留原 ID、注释、大小写、换行、顺序及完整记录；输出哈希在写入时计算。
   原始单条普通或单条未压缩长输入可复用；单条 gzip 长输入解压一次供当前
   仅支持普通 FASTA 的恢复引擎使用。
6. 计划或输入变化、漏记录、重复记录、取消、残缺 gzip 等不产生完成标记。
   准备成功只写 `complete_inputs_only`，**不表示比对或下游任务成功**。

初始风险规则是 query 长度超过当前 packed CIGAR 单操作上限，属于保守的
**query 消耗型风险指标**，不是“该序列必然报错”的诊断。短 query 仍可能遇到
超长 target-only deletion 或其他错误。本计划明确记录这项未覆盖风险；不能
把长度阈值包装成消除所有 minimap2 断言的保证。更全面的提前筛选需要后续
在原始候选链上下文中建立，不擅自增加任意缩窗/换参数重试。

## 候选执行依赖关系

```text
query 一次扫描 → 长度、记录范围、身份、分流计划
  ├─ 全普通 → 原输入 / 原生完整比对
  └─ 含超长
       ├─ 一次生成普通组及长记录输入
       └─ 一次构建或校验原默认参考索引上下文
            ├─ 普通组完整比对 → 首分段原生阈值上下文
            └─ 超长记录原始候选 + 分窗路径 + 接缝/候选/原生决策校验
                    ↓
              按原记录/原索引分段核对完成单元
                    ↓
              新的完整性放行规则（尚待正式集成）
```

不存在全输入试错节点、二分定位节点、单条崩溃复现节点。原索引如果本来多分段，
仍须逐一完整处理；“复用索引”不等于改成单分段，更不是改变 `-I`。
全长输入没有普通组时，需要首分段的 metadata-only 上下文取得路径，不能为取
阈值而故意对超长 query 做完整精细比对。此路径目前仅列入规划，尚未执行验收。

## 真实对照入口

`compare_proactive_mixed.py` 是维护者实验工具，默认 PLAN ONLY，显式 `--execute`
才运行。它从指定、不可变的已打包恢复 runtime 加载引擎，避免把未合入的分支
模块假装已经在主干提供。该参数不是客户产品配置。

- 小规模：10 条都可以原生完成，实验内暂时降低长度阈值，让 1 条走恢复。
  普通 9 条与完整原生 baseline 的对应 PAF **逐字节对照**；长记录与原生完整
  比对的几何、CIGAR、候选和已知原生标签对照。AS 不重建，不做全局 DP 等价声明。
- 大规模：使用已留存的确定性单记录 270 Mb 参考构造 9 普通 + 1 长的混合输入。
  长记录直接进入恢复，禁止原长 query 被送入未切窗的 `-c` 比对，不执行任何
  故意的断言复现。普通批次与独立普通 baseline 对照，长结果与解析的同一性
  几何/长度/MAPQ 契约比较；完整 CIGAR 和两份结果路径也经过现有校验。
- 普通组包含一条 N-only 无比对记录，完成单元按输入记录核对，而不是按 PAF 行数。
- 原默认索引只为候选流程构建一次。独立 baseline 明确标为 `independent_QA_only`，
  不计入生产流程执行次数；测试对照本身当然会增加测试耗时。
- 不发布正式 `result.paf`、不写成功检查点、不启动客户作业。

## 重复工作：当前去掉的与尚未去掉的

| 工作 | 状态 |
| --- | --- |
| 全输入先跑失败 | 候选实验不再执行 |
| 失败后二分分组重跑 | 候选实验不再执行 |
| 长单条再崩溃一次才准入 | 候选实验不再执行 |
| 每条长序列重扫整个输入以分组 | 一次统一物化，已消除 |
| 长度、字节范围、输入哈希分别重扫 | 一个扫描器同时计算，已合并 |
| 每个窗口重建参考索引 | 本实验复用同一个原始索引，不重新构建 |
| window/guidance 各自生成一份 normalized target/query | 冻结引擎内仍存在，后续共享只读存储优先处理 |
| 原版粗比对与 helper 原始链状态采集 | 仍独立执行，用于来源一致性核对；未验证不能删其中之一 |
| 对大型证据文件重复哈希 | 仍存在，需区分写入时身份、跨阶段变化保护与真正重复扫描 |
| 重叠窗口多算的碱基 | 保留必要接缝验证，报告实际额外碱基数；不是试错重跑 |

不以省时间为由删候选完整性或置信度检查。优先共享一份只读存储，保持其生命周期
和变更检测；再讨论能否将独立粗链对照移到离线验收。没有实际测量不报提速比例。

## 后续正式集成前仍需验收

- 混合多分段与全超长输入；保持原默认索引、阈值、输入分组和结果顺序语义。
- 去除断言收据依赖后的完整来源/候选/单元放行规则，不能简单删除旧门禁。
- 共享只读输入存储减少重复标准化；保留失败与输入变更拒绝行为。
- 普通批次已完成、超长失败后的分组级缓存与恢复，避免重跑普通批次。
- 新执行入口的完整 run.sh → 下游 → Full/Light 端到端验收。
- 原客户数据验收仍待执行；不拿合成同一性用例替代复杂小麦数据。

本阶段按仓库默认 Git 规则，仅将隔离规划器/实验入口/测试文档作为源码研究提交；
不合入旧的生产恢复接线，不改变当前 Server 命令，不修改 update.sh，不更新 Release。

## 本轮已执行的验证（2026-10-30）

- 新增 **25 项**规划器/输入准备/安全默认单元测试，全部通过，无跳过。
  包括普通与 gzip 单遍扫描、完整记录字节保持、阈值边界、全普通零副本、单长
  gzip 一次解压、多长记录单次物化、异常/取消/输入变化不写完成标记。
- 小混合真实 minimap2 对照通过：9 条普通 + 1 条 90 kb 测试长记录，内部测试
  阈值 64,000。普通组与完整 10 条原生 baseline 对应行逐字节相等，测试长记录
  与完整原生结果的现有路径/元数据契约相等。该降低阈值只发生在测试，不是产品参数。
- 真正超长混合对照通过：9 条普通 + 1 条 **270,000,000 bp** 长记录，使用真实
  268,435,455 上限规划。普通组逐字节对照通过（含一条 N-only 无映射），长记录
  直接恢复通过。没有完整超长 `-c` 试跑、没有故意失败、没有二分、没有单条复现。
- 候选流程只构建一次原默认索引；普通组提供实际首分段阈值。长记录 6 个窗口：
  270,000,000 core 碱基 + 1,000,000 context 碱基，共 271,000,000 碱基（额外约 0.37%）。
- 大混合输入大小 **270,022,803 字节**：规划读取恰好一遍，所有分组物化再读取
  恰好一遍，没有按长记录数量重读整份输入。**这不是整个恢复引擎的总 I/O**；
  冻结引擎的重复存储/校验读取仍在前表列明。
- 大控制候选子进程耗时之和 127.114 秒，其中窗口比对 49.377 秒、独立粗比对
  28.004 秒、helper 原始链状态 38.598 秒。仅为子进程耗时，**不含 Python 恢复、
  输入扫描/输出校验，也不是端到端耗时或提速倍数**。独立 QA baseline 另列为
  6.583 秒，不是产品重复任务。
- 复用的引擎为已冻结候选包的逐文件校验 runtime（原实现 `a8baea0`），没有修改
  其文件或 minimap2；planner/harness 自身 SHA 在每个报告中记录。
- 未生成正式 result.paf/成功检查点，未运行新入口的全套 Server 流程，未发布 Release。
  这批证据只证明主动分流与直接恢复的单分段混合控制，不等同于产品验收。
