## 修改 K 的候选，不等于已经测得客户提速

严格保持原顺序、完整 contig 和索引不变，预测批次如下：

| K（碱基数） | 每批 query 数 |
| --- | --- |
| 500M | 6, 9, 7, 11, 13, 9, 5, 7, 10, 9, 18, 20, 13, 30, 48, 240, 221 |
| 1G | 15, 17, 20, 13, 18, 32, 40, 87, 434 |
| 2G | 31, 31, 50, 115, 449 |
| 5G | 81, 595 |

`-K` 是进入批次的 query 碱基规模，不是内存上限。更多 query 同时做链计算和
DP 会增加内存；不能把 500M → 5G 理解为没有代价的十倍批量。不能由 Peak RSS
单点准确推断扩大批量后的内存，也不能以整机 RAM 代替作业预算。

本轮不改 `-I`、`-f`、预设、种子过滤、候选保留、参考分区、query 顺序或 contig
边界。改变这些会引入额外变量，不是这条最小提速路线的必要条件。

## 已执行的真实 minimap2 控制

本地 Linux / WSL 可见 16 个逻辑 CPU、进程 affinity 16 个 CPU。固定原版
minimap2 `2.31-r1302`，SHA-256：
`b6c81294dc0b68b2f54f8e2f6f3ad6be71a40bccc47a6e244ecebc73bae9501d`。

使用 8 个映射线程，确定性合成 64 条完整 query，含正反向、插入/缺失、重复候选和
3 条 N-only。单索引和实际双分区索引分别比较；各组内使用完全相同的 `.mmi`
字节，只改变 `-K`。重复顺序交错，以降低热缓存/运行顺序的影响。保留 GNU time
独立 wall / CPU / peak RSS，所有子进程超时/失败均拒绝推荐，不自动重试。

以下是 1 Mb/query、每组 3 次的中位数；**K 是缩小控制中的数值，不是客户推荐值**：

| --- | ---: | ---: | ---: | ---: |
| 单分区 | 2M | 8.28 | 1.98 | 51.45 |
| 单分区 | 8M | 3.93 | 6.90 | 154.66 |
| 单分区 | 32M | 4.29 | 6.50 | 203.71 |
| 双分区 | 2M | 9.43 | 1.95 | 68.36 |
| 双分区 | 8M | 4.89 | 6.64 | 200.25 |

较小的 250 kb/query 控制每组重复 5 次；另做了 1 Mb/query 的单线程对照。
合计 **52 次真实映射**：

- 同一索引内，所有 K / 重复 / 1 与 8 线程的对应 PAF 逐字节相等，包含顺序及全部
  CIGAR、MAPQ、评分和候选标签；不只比较行数或是否退出成功。
- 独立检查确认 61 个非 N-only query 有结果，正反向及含 indel 的 CIGAR 均出现。
- 参考与查询字节在运行前后保持一致；双分区确有 2 个原始 index part，不靠标签猜测。
- 单/双分区之间不作 PAF 等价声明，因为改变参考索引分区本身不是本轮变量。
- 1 Mb 控制中，2M → 8M 的中位提速分别为 2.11x / 1.93x，内存同时上升约 3 倍。
  继续增至 32M 没有更快、却进一步增加内存。
- 初始小控制曾因测试 `-I` 阈值没有真正形成双分区而被排除，修正后重新执行；
  不将该次错标的样本计入上述 52 次验收。

资源与哈希摘要见 `validation_ordinary_batch_20261105.json`。
这证明批量不足能够成为实际瓶颈，且在这些控制中扩大批量可以保持结果并提速；
**不证明客户整条小麦 query 会提速 2 倍，也不等于已验证 64 核扩展效率**。

## 面向客户的正确落地顺序

1. 先确认重跑作业实际可使用的 CPU 配额和 affinity，区分“请求了 64”与“允许用 64”；
   需要在同一计算作业环境测量，不能拿登录节点结果代替。
2. 普通组只改 K，保持完整 query、原 `.mmi` / 分区和其他参数，优先对照适度候选，
   同时度量实际 wall time 和峰值内存，不直接固定 `5G`。
3. 选择满足作业内存预算且能降低 makespan 的批量；若仍是单 query 长尾，继续定位
   重计算阶段，而不是为追求 CPU 百分比无限扩大 K 或重复整批比对。
4. 正式实现由 Server 内部根据原有线程/资源输入选择批量，用户仍只运行原 `run.sh`。
   这一步尚未接入本分支的生产路径；在真实数据/资源预算尚未验证之前不修改正式默认值。
5. 普通阶段已完成的客户结果属于主对话负责的续跑契约，本分支不重算、迁移或删改。

本分支当前交付的是可复现分析工具、已执行的参数控制和结论，不是已发布的自动提速版。
