# 小麦 Q0：保守快速路线（设计，尚未实现）

**可以少放置一段序列、少闭合一个 gap；不能为了少算而降低实际拼接的证据标准。** 这不是已有 `positive_threshold` 的行为说明，也不是可用的命令行选项。现行正式路线、默认值和已完成作业不变。

设计依据：同一份全麦首轮需求只有 5,599 段（12.75 Mb）。投回 61,000 个历史窗口时，1,917 个查询侧命中、57,374 个仅目标侧命中，按现规则仅能排除 1,709 个整窗。后者不是 mapper 次数或墙钟节省率。快速路线不再以这 61,000 个窗口为派活清单；它问的是：**做这一次计算，能否改变一个具体的放置或接头？**

## 算法如何分流

| 决策 | 快速路线拟采用的行为 |
|---|---|
| 建草案 | 从已验证的原始比对中，用染色体、方向、顺序相容的强锚点构建骨架。简单区段不做全套路径排名；有已观察到的冲突且会改变骨架时仅在该处消歧。仍无法确定归属或顺序的片段留作未放置，不用 N 把它硬接上。简单/复杂由证据判断，不交给用户逐组选择。 |
| 判断是否补证 | 对已达标的定位不再追查假想竞争者。同一位置的接头是独立问题：顺序和相邻关系有支持，但没有精确闭合证据时，可以原样留 gap。只有能指出候选来源、方向和区间，且结果可能改变关键放置或闭合接头时才派任务。仅在某个旧窗口的目标侧擦到请求，不足以派发整窗；也不一律丢弃目标侧，因为真正的配对证据可来自任一方向。 |
| 单个任务 | 优先用已有、身份相符的精确配对记录；近似锚链只为候选排序。对可能改变交付结果的少数候选，取必要侧翼做局部精比对；共享相同目标上下文的请求可合批。闭合或切换必须有方向、两侧坐标和精确匹配支持，且不能重复占用来源。预算用尽仍无证据就保留缺口或不放置，不自动扩大为整条原生比对或整麦全搜。明确区分“未搜”与“搜过无匹配”，不同目标上下文不冒用旧结果身份。 |

## 最小对照：局部补比对值不值得做？

在同一冻结输入上先比三条路线，阈值与候选预算在看答案前固定：

- **A，现行路线**：已有可比的正式结果就复用；仅有草案首轮清单的，不充作最终 Q0 真值。
- **B，零新增补比对**：仍使用已验证的初始 PAF，但从它们构建快速骨架，不拿 A 的获选路径或耗时较高的定位断点作捷径。这是速度和质量的基线，不是说初始证据免费。
- **C，在 B 上按需补证**：只给上述可改变决策的区间分配局部预算；保留一个真实依赖跨片段证据才能连接的案例，以及重复区或方向冲突的案例，不能只测容易跳过的区段。

分别报告从相同起点到可交付结果的总耗时、实际 mapper 调用与输入碱基；质量上比较新增错接/错向、多留的 gap 与未放置碱基、以及下游供体占用是否正确。不能用多闭合几个 gap 抵消一个错接。先看 **C 相比 B 花多少时间、可靠补回什么**，再看相对 A 的取舍；不凭整窗减少率或单个面板宣布取代正式路线。
