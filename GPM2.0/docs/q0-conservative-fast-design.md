# 小麦 Q0：保守快速路线（设计与隔离试算）

**可以少放置一段序列、少闭合一个 gap；不能为了少算而降低实际拼接的证据标准。** 这不是已有 `positive_threshold` 的行为说明，也不是可用的命令行选项。仅在冻结的 4D 输入上实现过隔离试算；现行正式路线、默认值和已完成作业不变。

设计依据：同一份全麦首轮需求只有 5,599 段（12.75 Mb）。投回 61,000 个历史窗口时，1,917 个查询侧命中、57,374 个仅目标侧命中，按现规则仅能排除 1,709 个整窗。后者不是 mapper 次数或墙钟节省率。快速路线不再以这 61,000 个窗口为派活清单；它问的是：**做这一次计算，能否改变一个具体的放置或接头？**

## 算法如何分流

| 决策 | 快速路线拟采用的行为 |
|---|---|
| 建草案 | 从已验证的原始比对中，用染色体、方向、顺序相容的强锚点构建骨架。简单区段不做全套路径排名；有已观察到的冲突且会改变骨架时仅在该处消歧。仍无法确定归属或顺序的片段留作未放置，不用 N 把它硬接上。简单/复杂由证据判断，不交给用户逐组选择。 |
| 判断是否补证 | 对已达标的定位不再追查假想竞争者。同一位置的接头是独立问题：顺序和相邻关系有支持，但没有精确闭合证据时，可以原样留 gap。只有能指出候选来源、方向和区间，且结果可能改变关键放置或闭合接头时才派任务。仅在某个旧窗口的目标侧擦到请求，不足以派发整窗；也不一律丢弃目标侧，因为真正的配对证据可来自任一方向。 |
| 单个任务 | 优先用已有、身份相符的精确配对记录；近似锚链只为候选排序。对可能改变交付结果的少数候选，取必要侧翼做局部精比对；共享相同目标上下文的请求可合批。闭合或切换必须有方向、两侧坐标和精确匹配支持，且不能重复占用来源。预算用尽仍无证据就保留缺口或不放置，不自动扩大为整条原生比对或整麦全搜。明确区分“未搜”与“搜过无匹配”，不同目标上下文不冒用旧结果身份。 |

## 最小对照：局部补比对值不值得做？

在同一冻结输入上先比三条路线，阈值与候选预算在看答案前固定：

- **A，现行路线**：已有可比的正式结果就复用；仅有草案首轮清单的，不充作最终 Q0 真值。
- **B，零新增补比对**：仍使用已验证的初始 PAF，但从它们构建快速骨架，不拿 A 的获选路径或耗时较高的定位断点作捷径。这是速度和质量的基线，不是说初始证据免费。
- **C，在 B 上按需补证**：只给上述可改变决策的区间分配局部预算；保留一个真实依赖跨片段证据才能连接的案例，以及重复区或方向冲突的案例，不能只测容易跳过的区段。

分别报告从相同起点到可交付结果的总耗时、实际 mapper 调用与输入碱基；质量上比较新增错接/错向、多留的 gap 与未放置碱基、以及下游供体占用是否正确。不能用多闭合几个 gap 抵消一个错接。先看 **C 相比 B 花多少时间、可靠补回什么**，再看相对 A 的取舍；不凭整窗减少率或单个面板宣布取代正式路线。

## 如果要求不降精度，优先保留正式草案

“少放一点”与“不降精度”是两种合同。前一种快速骨架不能作为后一种的起点。后一种从同一份正式草案和首轮请求开始，区分两类可以少算的工作：

- **结果已经确定。** 把仍缺证的定位或接头列为问题，而不是把相交窗口直接当任务。按原规则先查已验证 PAF 中该来源、方向、区间及对端的证据；一次读取可同时回答多个问题。一个定位已过线，不为它追查假想竞争者，但同一区域的未知接头、其他来源的定位及跨组占用仍要单独判断。对只问“是否有证据”的问题可以在已有正解时停止；如果还要选择哪个接头、切在哪里、采用哪个证据 ID，就不能靠先命中的记录改变正式顺序。只有窗口关联的**所有问题**都已解决，或能证明确实不可能影响正式结果，才可免算；不能把未搜索登记为阴性。队列优先查已有产物、且一旦回答便能免去多个昂贵窗口的问题；排序只改变工作顺序，不能改变正式的同分选路或接头选择。若正式消费者需要完整比对记录，就必须命中同一搜索的完整产物或做原计算。
- **结果未定，但同一运算做了多遍。** 原始查询与目标上下文（含目标顺序）、参数和工具均相同，才复用已验证的精确产物；不同输入不冒用命中。仍需比对的窗口先保留原参数与完整目标。建图时 `qualify_pair_blocks()` 会对不同放置反复构建同一来源对的竞争坐标索引；可试验在同一图内按有序来源对、策略和有效证据集惰性复用，不能跨歧义剔除或追加新证据错误命中。区间相交亦可只访问实际重叠部分；不能删去反向或另一个实际定位的记录。此项是待计时的实现候选，不是 4D 已有的加速结果。

在同一个冻结 group 上进行等价验收：不仅比最终序列，还比来源/方向/切点/接头与证据、参考缺口、占用与可用供体、未放置部分、已知备选及歧义，并比下一轮请求。对仍需完整搜索的窗口，另比原始或合同规定的逐目标/方向投影。分别记录冷启动墙钟、命中已有产物的续跑耗时、真正新启动的 mapper 次数和长尾，不按计划窗口比例估全麦。已观察到同一正式阈值在 3B 面板冷测从 62.51 到 6.24 秒、7A 从 11.62 到 12.75 秒，九类交付字段均无差异；见 `incident-tools/wheat-20261119/q0-formal-threshold-20261123.json`。它们是面板结果而非全麦保证。

## 冻结 4D 实测（非正式交付）

同组 766 个来源、1,074,672,025 bp、1,212,752 条配对记录，同 x86 节点、8 核。A 从同一组输入重现 `44e274a7` 的 4D 草案序列和首轮需求，不是补证完成的最终 Q0。B/C 不读 A 的赢家；C 的局部比对并不保证与原窗口完整搜索等价。耗时从已暂存输入开始，含读取和结果写出，不含排队及共同暂存。

第一版（作业 `43060314`、`43060320`，比较 `43060326`）：A 用 544.23 秒、1 条骨架、95,956,126 bp；B/C 约 229.77 秒、1 条骨架、仅 24,183 bp。整段内部只要含歧义就整段放弃，导致 62 个候选被否决，C 没有合格的补证任务。**不采用**；不能把少交付近 96 Mb 计作优化。比较结果：`incident-tools/wheat-20261119/q0-fast-4d-pilot-v1-20261125.json`。
