### 2.2 文字与布局现状

- App 字体栈是 `system-ui, -apple-system, "Segoe UI", "Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", sans-serif`。当前自绘提示继承此体系，不是单独打包的跨平台统一字体。
- Final Path 信息已有明确语义：名称、采用片段长度、来源 Contig 总长（可得时）、来源区间、方向。两种长度不可为了统一样式而混成一个“长度”。

### 3.3 不能仅靠替换 title 的原因

- 动态代码会重新写入原生 `title`，必须同时迁移更新来源。
- `ui/i18n/presentation-patch.js` 对可更新属性有白名单；新增统一 Tooltip 属性需要接入原位语言切换，不能出现按钮已换语言、提示仍是旧语言。
- 禁用按钮/导航入口的“为什么不可用”也要有可靠提示命中区；不能为此把禁用业务操作重新启用。
- 当前即时 runtime 与比对 runtime 是不同 owner，尚没有全 App 单一激活提示的统一协调。后续需要处理嵌套命中和旧提示替换。
- 设置页属于原生 `<dialog>` 场景，提示需留在正确的 top-layer/对话框所属层；不能假定往 body 放一个极高 z-index 就能盖过所有对话框。
- 页面切换、Assembly DOM 缓存、项目/染色体切换和原位 patch 都是生命周期边界；应取消计时器、隐藏旧提示、清理失效 ARIA 关联，不重建业务视图。
- `snapshotWithoutFinalPathSelection()` 已在导出克隆中恢复 Final Path `<title>`。此“App 内自绘、独立 SVG 保留信息”的契约必须保留。

## 4. 已确认决策与待讨论方案

D1 的配色规则、D2 的单一规格、D3 的即时触发/定位/关闭/长内容交互均已确认；用户对最后一组交互规则回复“可”，授权按定稿规范和 D4 边界在 master 开始实现。用户后续明确要求覆盖此前相冲突的草案建议；每次简短确认仅覆盖当次提出的方案。

### D1. 同一套规范，仅颜色按对象覆盖（已确认）

- 用户进一步明确：不只是比对块，还包括 ctg 及其他所有有明确对象颜色的场景；没有明确对象颜色时，按统一规范的默认配色处理。
- 统一关系是“统一 Tooltip 规范 + 可选的对象颜色覆盖”：有色/无色对象共用同一套组件与样式规则，不按比对、ctg 或其他业务各做一套。
- 对象是否有颜色只影响颜色类参数，不改变字体、字号、排版、尺寸规则、内边距、圆角、阴影和触发方式。尺寸可随内容自适应，但遵循共同规则，不因有色/无色而分叉。
- 默认配色属于统一规范；仅在对象有明确颜色时覆盖。下列默认色值和文字/边框规则已获单独确认；此确认不恢复“所有对象统一中性底色”的旧建议。
- 用户明确要求：“根据对象的颜色决定悬浮框的颜色”，不仅匹配色系，也匹配对象的颜色深浅。
- 对有明确颜色的对象，Tooltip 背景以当前被悬浮对象的实际显示颜色为依据，而不是只按对象类别分配一套固定底色；无明确对象色的普通控件、路径等使用统一规范的默认配色。
- 比对示例：两种比对色分别对应各自色系；同一色系内的浅色比对块配浅色提示、深色比对块配深色提示，跟随该块当前显示的色阶。不能仅将所有主数据比对统一为一种蓝、所有辅助比对统一为一种棕。
- Contig、成员卡片、参考对象、GRT 等其他有明确对象颜色的场景也遵循同一原则；统一的是颜色来源规则，不是把所有提示染成同一种颜色。
- 对象若通过透明度/混色表现深浅，匹配目标是实际可见颜色；不能仅复制同一 alpha 值却因提示下层背景不同而产生另一种深浅。具体取色/合成方式待实现时核查。
- 只调整 Tooltip，不反过来改变对象颜色、identity 色阶、角色或生物学含义。
- 文字/边框需保证在对应背景上可读；允许的颜色调整也属于统一规则，不给有色对象额外引入一套字体或布局。不把默认配色强行套到有明确颜色的对象上。
- 此前“所有提示统一中性底色、角色色仅作小色标/边线”的建议已撤回，不作为实现依据。字体、圆角、尺寸、阴影等外壳参数按已确认的 D2 单一规格执行。

#### 默认配色及文字、边框规则（已确认）

仅对没有明确对象色的 Tooltip，使用以下默认配色：

| 模式 | 背景 | 文字 | 边框 |
| --- | --- | --- | --- |
| 浅色 | `#ffffff` | `#1e293b` | `#cbd5e1` |
| 深色 | `#223044` | `#e5edf7` | `#42546a` |

有明确对象色的 Tooltip 不套用上表背景：

- 背景严格匹配被悬浮对象的实际颜色及深浅。
- 文字根据背景明暗选择深色或浅色，保证可读；不为了让文字清楚而擅自改变背景颜色。
- 边框使用同色系略深或略浅的颜色，宽度仍统一为 1px。
- 上述配色规则适用于比对块、ctg 等所有有明确对象颜色的场景；不产生额外的业务样式分支。

### D2. 单一规格的字体、尺寸和信息排版（已确认）

用户已对以下一组参数回复“可”。所有对象使用同一规格，不再采用此前草案中的两种内容密度。

| 参数 | 已确认值/规则 |
| --- | --- |
| 字体 | 跟随 App 字体，不另设 Tooltip 专用字体或引入字体包 |
| 正文字号 | 默认约 13px，采用 `--font-small`（0.929rem）；跟随界面字号缩放，不受图内字号设置影响 |
| 标题 | 与正文同字号，字重 600；单句提示不额外添加标题 |
| 正文 | 字重 400，行高 1.5 |
| 排版 | 名称在首行；详细信息按“字段：值”逐行排列，长值自然换行；数值与 `bp` 不拆开换行 |
| 宽度 | 按内容自适应，不设强制最小宽度；最大 480px，同时不能超出窗口 |
| 内边距 | 统一上下 6px、左右 8px |
| 圆角与边框 | 圆角 6px，边框 1px |
| 阴影 | 统一使用 App 的轻阴影 |
| 信息完整性 | 完整名称、路径、坐标等不在提示框内再次省略；不静默裁掉关键字段 |

- 比对块、ctg、成员卡片和普通按钮全部遵循此表；仅内容不同及 D1 规定的对象颜色覆盖，不按业务或有色/无色分叉样式。
- 短提示自然收窄、详情按内容增大，但都遵循同一宽度上限和同一内边距；此前最大 320px/480px、内边距 6×8px/8×10px 两种密度的建议已撤回。
- App 字体栈沿用现有配置，不承诺 Windows/macOS 字体栅格化像素完全相同。

### D3. 即时显示、定位、关闭及长内容交互（已确认）

- 所有 App 自有 Tooltip 显示延迟统一为 0ms，不保留普通提示 300ms、比对/GRT 500ms 或其他非零等待；不增加淡入/淡出等待。
- 鼠标首次进入有效对象时，在指针右下方偏移 14px 显示；显示后位置稳定，不追随鼠标，切换对象时重新定位。
- 自动翻转、避让；距离窗口边缘至少 8px，不遮住当前指针位置。
- 控件获得键盘焦点时即时显示，相对控件定位；Esc 关闭，不抢焦点，关闭后不因同一次 focus/move 立即重弹。
- 鼠标可移入提示框继续查看、选择文字；从对象跨越间隙移到提示框不误关。离开对象和提示框的关联区域后立即关闭，不增加关闭计时器。
- 长内容自动换行；超过窗口可用高度时框内滚动，不省略或裁掉内容，内部滚动不关闭。
- 开始拖动、打开右键菜单、外部滚动、切换页面/项目、窗口失焦时关闭，清理失效 owner/ARIA 状态；拖动中不弹出。
- 悬浮不改变选择、数据或视口，不新增操作按钮；设置页 `?` 原有点击展开功能保留。
- Tooltip 关闭规则不改变已有业务菜单/成员面板/染色体选择器的 400ms 关闭规则。

### D4. 技术边界与迁移策略（随定稿实施）

- 建议统一 App Tooltip runtime + 样式 token；按普通控件、图形数据、设置说明提供适配器，而不是各页复制定位与计时器。
- 同一时刻只保留一个激活 Tooltip；嵌套子对象优先，移动时不同时弹出父/子或原生/自绘两层。
- 普通内容安全地当作文本；字段模型用 DOM 安全构造，不把路径、Contig 名或错误信息当 HTML 执行。
- 显式迁移 App 自有 `title` 来源及动态更新，保留 `aria-label`/`aria-describedby` 等语义；不靠一段无差别删全页 title 的观察器掩盖遗漏。
- 普通控件覆盖 pointer 与 keyboard，纯图形不为每个非交互形状强塞 tab 停靠点。
- 对话框/弹出层按所属 surface 挂载；覆盖标题、关闭按钮、表单内容、原生顶层 dialog 的可见性与焦点边界。
- 先统一 runtime 和已自绘的几类，再迁移 shell/项目/Overview，随后完成 Assembly/SVG 和动态 title 的清点。
- 不改变数据来源、Contig/区间语义、Preview 的完整源对象与采用覆盖、选择/拖动/右键/缓存和导出结果。

### 7.4 用户截图回归：长路径换行后的多余留白

- 观察：用户提供的 Windows App 截图中，项目路径已换成两行，但提示外框右侧仍有明显空白；该截图只证明这一显示问题，不代表整套原生交互已验收。
- 原因：`width: max-content` 达到 480px 上限后，路径在连字符等自然断点换行，外框不会继续贴合换行后的最长一行。不是需要缩短路径、截断信息或增设另一套路径提示规格。
- 修正：共享 runtime 在显示时读取实际文本行片段的右边界，按最长一行收紧外框，保留原有内边距、边框和垂直滚动条占位；保留 1 CSS px 的分数像素余量。原 480px / 窗口上限、完整内容、颜色、字体及即时显示规则不变。
- 生命周期：切换对象或原位文案更新时先清除上一次测得的宽度，再测量新内容；同一对象内移动鼠标不反复测量或改变定位。定位使用收紧后的实际宽度，继续遵循原窗口边距和键盘锚点规则。
- 验证：新增 6 个定向案例，包含截图同类完整路径、同一行多个片段、滚动条与分数像素、上限、新对象/文案重算、空测量回退及鼠标/键盘窗口边缘定位。测试使用显式布局片段验证尺寸计算，不冒充浏览器或原生排版证据；最新全量测试及构建结果见 7.2。修正后的 Windows App 实际效果和 macOS 原生交互仍待验收。

- 用户补充：`bp` 不用独立成行；第二张截图明确是装配页主数据集的 ctg 提示，随后又提供比对块存在同类右侧空白的截图。修正共享显示规则，不为 ctg / 比对块各设固定宽度，不改颜色、字号、480px / 窗口上限及即时触发。
