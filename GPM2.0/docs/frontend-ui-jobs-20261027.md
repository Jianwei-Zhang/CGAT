## 1、2：分型轨道与 Final Path 同步

### 已确认的行为边界

用户确认：“增删轨道后立即同步 Final Path 和按钮状态，但不自动把主路径覆盖为预计算结果”。

- 轨道新增或删除成功后，同步 Final Path 的相关显示及预计算路径按钮，不依赖切页、重载或额外点击。
- 新增分型轨道后，按分型状态隐藏“预计算路径”入口。
- 删除全部分型轨道后，恢复主路径上下文和适用的“预计算路径”入口。
- 恢复入口不等于执行恢复操作；不得因此自动以预计算结果覆盖用户主路径。
- 轨道删除所涉及的关联数据处理与“恢复预计算路径”是不同操作，不得混为一体。

### 待实现时核实的验收细节

- 按当前染色体作用域处理，不影响其他染色体的路径或轨道状态。
- 覆盖第一条轨道新增、非最后一条轨道删除、最后一条轨道删除，以及重新进入页面。
- 无可用预计算基线时，不显示无效入口；已处于预计算路径时，保留当前禁用语义。
- 创建或删除失败时，不提交虚假的成功状态；清理成功删除后失效的分型路径选择。
- 不通过整页重载实现联动；不重置无关视口或用户编辑。

## 6：主视图工具区重排（已确认，未实现）

用户追问：能否让“预计算结果”“分型轨道”和其他控件同级，参与重排对齐？

用户确认：标题独立，所有工具控件同级整组换行。取消这两个操作独占标题右侧的特殊布局，让全部工具控件进入同一个可换行容器。

- “主视图”标题保持独立标题行，不参与参数控件布局。
- 标记显示、辅助数据集选择、Contig 长度、比对长度、一致性、历史操作、预计算结果、分型轨道作为同级控件组参与布局。
- 同级是指布局层级一致，不代表把复选控件和按钮改成相同语义，也不强制相同宽度。
- 一组包含其标签、输入/选择框、单位及紧密关联操作；组内不拆行。
- 统一控件高度与组内垂直对齐，各行左对齐，固定间距；保持固定 DOM/阅读顺序。
- 优先用 CSS Flex 换行，不按测量结果反复切换 Flex/Grid 或搬动控件。
- 控件优先按内容占宽，不平均拉伸；超长名称在控件内部截断，不挤出容器。
- 进入下一行时允许工具区高度增加，但不允许临界宽度反复来回跳动。
- 尺寸变化、语言切换不重建页面，不重置焦点、菜单、选择或视口。
- 后续验收覆盖中英文、长数据集名称及临界宽度；不新增强制最小窗口宽度。窗口窄到单个完整参数组也放不下时，仅工具区内部横向滚动，不拆组、不缩小字号、不撑宽整个页面；第三轮 Q12 已确认。

本方案已获用户确认，替代此前“标题右侧保留预计算结果和分型轨道、参数单独换行”的建议。

## 5：术语与命名（原则及示例已确认，未实现）

### 用户提出的大小写规则

- 大标题使用每词首字母大写，例如 `Main View`。
- 小标题、字段标签使用首词首字母大写，例如 `Alignment length`。
- 系统提供的选项显示文本使用每词首字母大写。
- 按钮及菜单动作使用首词首字母大写，例如 `Add phased track`、`Restore deleted contigs`；专有名词保留标准形式，不与选项值规则混用。
- 专业名称和单位保留标准形式，例如 `LGZ`、`FASTA`、`bp`、`Mb`。
- 数据集名、项目名、Contig ID、文件路径等真实数据保持原值；不修改内部字段或枚举值。

### 已确认：去冗余、保含义

用户提出：`Auxiliary ds ctg len` 中能否直接不要 `ds`？

用户确认：不是机械地将全部 `ds` 展开为 `Dataset`，而是按标签实际指代消除冗余；采用下列示例措辞。

| 场景 | 已确认英文 | 已确认中文 |
| --- | --- | --- |
| 辅助 Contig 长度字段 | Auxiliary contig length (bp) | 辅助组装 Contig 长度 (bp) |
| 辅助数据集选择字段 | Auxiliary dataset | 辅助数据集 |
| 主数据集成员区域的大标题 | Primary Dataset Members | 主数据集成员 |

- 长度字段的对象是 Contig，因此可省略 `ds`；`ctg`、`len` 展开为 `contig`、`length`。
- 真正选择数据集或标识数据集成员的场景仍保留 `dataset / 数据集`，避免丢失对象含义。
- 长度字段采用“辅助组装 Contig 长度 (bp)”，不自行进一步简写；其余全 App 词条按上述原则整理，含义有歧义时再确认。

## 10：主数据集成员浮层（已确认，未实现）

### 源码初查

- 成员面板目前使用 `.assembly-members-panel-inline` 参与顶部布局，展开内容仍在正常布局流内。
- 当前卡片网格以 `290px` 为列最小宽度基准（窄容器时受限于容器宽度），再用 `1fr` 拉伸；卡片最小高度为 `78px`。因此并非纯固定宽度，但确有较强的尺寸下限和拉伸约束。
- 成员 Ctrl/Cmd 选择会经过 `updateTrackSelection()` 并调用 `rerender(host, store)`；这是需要追踪的重绘入口，不足以单独认定所有点击闪烁的根因。

### 已确认的交互与样式方案

- 顶部仅保留紧凑的“主数据集成员 / Primary Dataset Members”触发器，点击在其下方展开浮层；不再撑高或挤压主视图。
- 下方空间不足时调整浮层位置，限制在窗口内；成员多时仅浮层内部滚动。
- 点击成员后浮层保持打开，支持连续切换及现有 Ctrl/Cmd 多选、框选和业务右键操作；不把选择操作改成打开/关闭面板。
- 再次点击触发器、点击浮层外部或按 Esc 时关闭；保留鼠标移出自动收起，沿用现有 400ms 延时。按钮、成员面板及其所属业务菜单作为关联区域，内部移动不误关，重新移入取消关闭。
- 按内容自适应卡片宽度，短名称不强制占据整列，不平均拉伸；采用下文已确认的两行等高结构及信息分层，来源区间和局部详情移入提示，不额外撑高卡片。
- 卡片采用紧凑间距，长名称省略但可查看完整值；保留角色颜色，选中用边框/轮廓等额外标识。
- 普通选择只更新必要的选择状态和关联视图，不重建整个成员浮层或整页；保留浮层打开状态、内部滚动、焦点和不应变化的视口，不取消已有明确定位语义。
- 对实际选择链路和 DOM 替换范围做定向排查，不用动画或仅保存滚动位置掩盖闪烁。

### 用户纠正：半行是现状，不是设计目标

用户明确：“单张 contig 卡片目前是会占据半行，我想要的效果是 contig 卡片怎么设计更紧凑准确，而不是占据空间”。

- 此前助手将现状错误解读为“单张卡片最大半行”，并误记为已确认约束；现撤销该约束及其宽度计算公式。
- 目标是减少无效占位，同时准确表达成员身份、长度、片段来源及必要状态，不是设定半宽、两列或其他固定列比例。
- 浮层尺寸与卡片尺寸分别设计，不再从“半行”推导任何目标宽度。

### 已确认：固定两行、各类型等高、宽度紧凑

用户明确：“可以固定两行，普通的也是 ctgname 一行，长度一行，这样确保所有类型卡片的高度是等高的，宽度可以实现紧凑准确”。

- 撤销此前“普通卡片单行、特殊片段再增加信息行”的提案。
- 第一行显示 Contig 名称；第二行显示长度。普通、拆分/派生及其他类型卡片统一两行高度。
- 使用一致的行高及上下内边距获得等高效果，不沿用不必要的 78px 最小高度，也不依靠缩小字号实现紧凑。
- 宽度按两行内容合理收紧，按原顺序自然换行；不平分整行、不拉伸填满、不设半行比例约束。
- 选中只更新必要样式，不改变卡片外框尺寸、内边距或字重，不因此触发换行和闪烁。

### 已确认的特殊信息呈现

- 第一行保留名称中的片段身份；第二行保留长度，必要状态使用紧凑标记同排，不添加第三行。
- 来源区间、完整名称、局部成员详情等在受控提示/详情中完整呈现；卡面上保留必要的片段和状态识别，不能让不同片段变得无法区分。
- 状态较多时使用有明确说明的汇总标记，不无限加宽或撑高卡片，不静默丢弃状态信息。
- 长度摘要保留单位，完整信息给出精确 bp；片段长度、原始总长、源区间和路径坐标不混用。
- 长名称只在必要时省略，提供完整值；后续用长短名称、拆分片段、多状态及窄窗口验证可读性和等高效果。
- 上述卡片信息分层与浮层开关已在 grill-me 第一轮确认；第二轮 Q11 确认使用应用控制的即时详情提示，进入即显示、离开即隐藏。
- 同一卡片内名称、长度及状态之间移动不闪烁，提示只读、不拦截点击或拖动、不改变选择、不重建页面；不扩散修改其他类型提示的延时。

### 源码初查

- `final-path-graph-drag-runtime.js` 当前 pointerup 在未触发拖动时虽然提前返回，仍会执行 finally 中的 cleanup，而 cleanup 调用 `deps.rerender()`。这是普通点击也重绘 Final Path 卡片的明确源码路径，不等同于已经完成原生闪烁根因验证。

### 已确认的交互

- 图模式点击 Contig 片段、表模式选择对应行，均选中同一个 Final Path 路径片段实例；两个模式共用选择状态，切换模式时保留仍然有效的选择。
- 本轮 Final Path 只做单选，不新增 Ctrl/Cmd 多选；主视图和局部视图现有多选保持不变。
- 主视图及已打开的局部视图中，按该路径片段实际使用的来源区间产生高亮，不是将匹配到的整条 Contig 统一置为选中。
- 表模式点击或键盘聚焦某行的输入框，也选中该行并联动高亮；输入仍正常编辑。纯选择不提交数据、不触发重绘，不拦截文本选择、拖动排序及业务操作。
- 坐标输入尚未提交、验证或保存未成功时，高亮仍使用最后成功提交的来源区间；仅在新值成功提交后局部更新。无效输入或保存失败不改变有效高亮，不新增逐字符实时预览。
- 在主视图或局部视图主动选择对象时，清除此前 Final Path 选择及其关联高亮；单纯悬浮、滚动、缩放不清除，不改变数据或局部组成。
- 同项目、同染色体、同路径短暂切到其他页面再回来，保留有效选择；切换染色体、路径或项目则清除。App 重启不恢复此临时选择，片段删除或失效时立即清除。
- 点击另一片段替换这次选择；点击 Final Path 图形空白处清除此选择及其关联高亮，不清空无关编辑状态。悬浮仅显示提示，不改变选择。
- 不自动将 Contig 添加进局部视图，不打开或重组局部视图；没有对应对象时仅显示能建立可靠关联的部分。
- 默认只联动高亮，不自动滚动、缩放或改变视口；是否需要额外定位功能另行讨论。
- 保持主/辅助/参考角色颜色；使用附加轮廓等方式表达选中及关联状态，不改变片段几何、长度、标签排布或卡片尺寸。

### 关联与编辑安全边界

- 按项目、路径/染色体、路径片段实例、来源数据集/Contig 身份及区间建立关联，不能仅按名称或共享父 Contig ID 将无关拆分片段一起点亮。
- 同一来源在路径中重复出现时，只有被点击的路径实例是直接选中；其他视图的关联高亮与路径实例选中保持可区分。
- 反向、拆分、派生和分型片段需按实际来源映射；源坐标与路径坐标不可直接混用。GAP 不冒充 Contig 建立关联。
- 跨视图关联高亮不能隐式扩展删除、移动等操作的选择集合；保留现有业务选择及右键目标语义，视觉关联与可编辑选择分开处理。

### 用户补充确认：必须是来源区间级高亮

用户明确：Final Path 使用 ctg1 的后半段时，无论从图模式还是表模式选中，主视图和已打开且含 ctg1 的局部视图都只高亮该后半段，而不是整个 ctg1。

- 统一选择描述至少包含项目/路径作用域、路径片段实例、真实来源身份、实际采用的源区间及方向，不把 `Contig ID` 当成足够的高亮信息。
- 每个目标视图先解析其对象实际覆盖的源区间，再与 Final Path 所选区间求交，最后按目标对象的方向和显示几何转换为局部高亮范围。
- 示例按 1-based 闭区间说明：ctg1 长 10,000 bp，Final Path 采用 `[5,001, 10,000]`。主视图显示完整 ctg1 时，只标记 `[5,001, 10,000]`；局部成员若只显示 `[4,001, 8,000]`，只标记交集 `[5,001, 8,000]`。实现须遵循各数据层实际坐标约定并显式转换，不引入端点偏差。
- 同一源区间在反向显示时可能位于屏幕左侧，不能把“源后半段”简单解释成“屏幕右半段”；同样不能直接将 Final Path 累积坐标当作源坐标或参考坐标。
- 主/局部视图如果把源对象拆成多个片段，分别对每个对应片段求交，只覆盖相交部分；没有交集不高亮。
- 所选区间的精确覆盖通过局部描边或覆盖层表达，不用整条 Contig 的 `is-selected` 样式替代；原始填充色、未采用区间及实际序列内容保持不变，不为显示高亮创建真实切割。
- 局部视图未打开或不存在对应来源对象时，不自动打开或添加；映射数据不足时不退化为整条高亮，避免造成错误提示。
- 来源区间随路径编辑变化后应重新校验选择；片段删除、项目切换或选择失效时清理对应高亮，不能遗留旧覆盖层。

### 已确认：导出不包含临时选择效果

- 本轮新增的临时选中、来源区间关联高亮和悬浮效果默认不进入 PNG/SVG 导出。
- 生成导出图时排除新增的临时覆盖层/样式，不改变原有角色颜色、实际数据、导出范围和此前已有导出语义。
- 页面选择与导出隔离，不能通过先清除用户选择再截图来造成页面闪烁或状态丢失。

### 必须覆盖的区间回归用例

| 场景 | 预期 |
| --- | --- |
| 图模式选中 ctg1 后半段 | 主视图及符合条件的局部视图仅高亮对应源区间 |
| 表模式选择同一路径行 | 与图模式产生完全一致的区间高亮 |
| 图/表模式切换 | 保留同一有效路径片段选择，不扩大高亮范围 |

## 12：染色体选择器按钮式收纳面板（已确认，未实现）

用户最初希望下拉框可展开为更大面板，呈现全部染色体选项；随后提供现状截图，要求选项框/面板更简洁优雅，偏好按钮式点击收纳。

### 当前结构与截图问题

- 当前是单列带边框的大选项列表；每项显示染色体名称、Contig 数量及带千位分隔的完整 bp 长度，截图中列表需要纵向滚动。
- `render-tracks.js` 的选项本身已是 `<button>`；问题不在于缺少按钮元素，而在于单列满宽、视觉尺寸及展开层级。
- `.chr-picker-menu` 当前为宽 260px、最大高度 320px 的浮层；`.chr-picker-option` 使用 `width: 100%`。
- 当前鼠标离开后延时关闭，`selectChromosome()` 也会关闭菜单；新的收纳策略需要显式修改状态处理，不是只更换样式。

### 已确认：一个入口、两种状态

- 用户确认本方案替代此前“先开小下拉，再点展开大面板，再区分收起/关闭”的多级方案，并明确要求保留鼠标移出自动收起。
- 将当前染色体名称与箭头组织为一个清晰的按钮入口，例如“染色体 NC_141021.1 ▾”；点击打开面板，再点同一入口收起，箭头同步变化。
- 仅保留“收起 / 展开”两种展示状态，不另设放大按钮、重复标题或独立关闭按钮；点击外部及 Esc 也能收起。
- 展开为同一锚点下的紧凑多列浮层，不打开新页面、不挤压主视图；保留触发入口可点击，避免浮层覆盖它。

### 选项按钮的紧凑设计

- 选项依然是清晰可点击的两行按钮：第一行完整染色体名称，第二行 Contig 数量与有单位的长度摘要。
- 多列网格按可用空间排布，宽屏可容纳数列、窄屏减少列数；各按钮等高，列宽容纳常见名称，不拉伸成一整行大卡片。
- 使用薄边框、轻背景和紧凑内边距；当前项使用明确的选中描边/底色，与普通 hover 区分，不增粗外框导致位移。
- 长度摘要可将截图中的 `62,108,775 bp` 显示为 `62.11 Mb`，完整提示保留精确 bp；仅改格式，不改变 `placedBp` 等现有数据来源或统计含义。
- 不缩写或重编号真实染色体名称，不去掉版本后缀；必要时省略显示并提供完整名称，保留可区分性。
- 全部可选染色体属于同一面板，不分页隐藏；数量较多时内部滚动，不承诺无限选项都能同时放进一屏。
- 不新增搜索、分组或多层工具栏，除非后续实际数量证明需要。

### 已确认的交互与实现边界

- 选择染色体后保持面板展开，便于连续切换；同一入口、点击外部或 Esc 收起。
- 保留鼠标移出自动收起：以触发按钮与面板的联合区域为边界，区域内部移动不关闭；离开后沿用现有 `FLOATING_MENU_CLOSE_DELAY_MS`（当前 400ms）宽限期，重新移入取消关闭，不改全局默认值。
- 若浮层使用不同 DOM 挂载位置，须显式关联触发器和面板，避免从按钮进入面板或跨越二者间隙时被误判为离开。
- 第 12 项的移出策略曾单独确认；随后 grill-me 第一轮 Q1 也明确确认第 10 项采用关联区域内不误关、移出 400ms 后收起的规则。
- 展开/收起只改变选择器显示状态，不改变当前染色体、不加载主视图、不重建整页；选择染色体仍走现有业务加载流程。
- 选择成功后更新入口名称和当前项标记，失败时不伪造成功状态；保留既有异步请求有效性保护，防止快速切换后旧结果覆盖新结果。
- 项目切换后关闭面板并清理旧项目选项；不额外引入跨会话持久化要求。
- 触发器提供明确的展开状态和面板关联；键盘可到达各项，Esc 后焦点返回入口。
- 方案已确认，尚未实施；验收包括触发器到面板的移动、移出延时、重新移入取消、连续选择及开关不重建主视图。
