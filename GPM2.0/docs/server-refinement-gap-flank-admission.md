# Post-LGZ 接纳：分开验证缺口补丁和已有侧翼

原生工具输出不等于 CGAT Final Path。例：公开 Col-0 的 LR_Gapcloser 原生结果
与 DEGAP 补入的 463 bp 完全相同，但同一条 read 又把已有右侧翼的 A18 变成了 A19。
原组装和 TAIR12 都为 A18，精确跨位点的两条原始 CCS reads 各支持一种；不能把 A19
判作已证实的纠错，也不能仅因不同于参考就判作错误。

## 接纳规则

1. 先按原有契约用 LGZ 来源、原生读段和迭代坐标重建原生 FASTA；保留原生产物和回执。
   原生 trace 只能证明候选从哪来，不能授权附带改写已有序列。
2. TGS-GapCloser、quarTeT、LR_Gapcloser 的正向原生 trace 中，已和 LGZ 精确相同的外侧及
   唯一、未变的内侧岛仍使用 LGZ 来源。若剩余候选同时覆盖缺口与已有侧翼：对于单个缺口，
   用可唯一定位的、紧邻缺口的 31 bp 精确碱基锚定位被卷入的那一侧；另一边可以沿已有验证的
   原生 trace 边界。只有定位唯一、顺序一致，并且证据能区分填补和侧翼替换时才截取缺口补丁。
   保留原侧翼；接受修改的记录单独保存未接纳侧翼的区间、理由和长度差，报告不把它算成缺口失败。
3. 不能定位、重复/交叉锚、或跨多个缺口却无法证实中间已知区间原样保留时，不猜切点。
   拒收相应不可拆分部分、保留原生证据和 LGZ；报告写明是无法拆分，不是原生运行失败。
   缺口内的部分填充继续支持。无新增序列、证据精确证明为重复侧翼的重叠连接仍可接纳，
   删除非重叠已有片段不接纳。DEGAP 已有的封存双向接点（含其独立审核通过的侧翼修改）不因
   此规则降级，但原生批量候选不能默默替换多个缺口之间的已知组装岛。
4. 不拿 TAIR12 作接纳条件，不自动排名，不把通过结构和来源审查称为生物学正确性。
   已有发布保留为历史；新规则的接纳配方与旧版不同，但同一原生回执仍可复用。

## 验收

- 单侧、双侧唯一锚；同聚碱基/重复锚、多缺口不可拆；精确重叠 vs 非重叠删除；部分填充；
  独立 DEGAP 接点和来源契约回归。报告能区分「闭合且保留侧翼」和「无法拆分，未接纳」。
- SSH 180 用此前同一公开 Col-0 数据和冻结 LGZ；同区间 LR 的 463 bp 缺口补丁与 DEGAP/TAIR12
  相同，右侧 A18 从原 LGZ 来源重建，原生 LR 仍保留 A19 等证据，Full/Light 与报告复核通过。
  未变化的工具（TGS 无候选、quarTeT 无候选）仍保持原有语义；校验新旧接纳区分、原生复用和
  q0–q3/PAF/基线终版不变。不改动上一轮工作区或 `master`。

### 2026-11-22 验证结果

Donau ARM 作业 `43016427` 成功。在独立工作区用同一份 Col-0 组装与 HiFi reads 先跑 LGZ-only，
再用 `run_all.sh --hifi … --gapfill-tools degap,tgsgapcloser,quartet,lrgapcloser` 补跑四个工具。

| 工具 | 结果 |
| --- | --- |
| DEGAP | 闭合 1 处，补入 463 bp。 |
| TGS-GapCloser | `completed_zero_accepted`，没有补丁接纳，未改变基线。 |
| quarTeT GapFiller | `native_no_candidates`，未改变基线。 |
| LR_Gapcloser | 闭合 1 处，Final Path 仅替换 `[100000, 100463)`；右侧翼保留 LGZ 的 A18。 |

LR 和 DEGAP 的交付 FASTA 逐字节一致（200,463 bp）。用唯一序列锚定位后，463 bp 与 TAIR12
一致；TAIR12 仅用于复核，不参与判定。LR 原生 FASTA 仍为 200,464 bp、保有 A19；报告显示
「闭合 1、拒收 0」，缺口明细另列「保留 LGZ 原侧翼」及原生 `+1 bp`。这不等同于判定 A19 错误。
按新规则再次接纳时复用同一原生回执，未重跑 LR，也未改写原生证据和已发布结果。

四个工具的 Full/Light 交付均通过重建及归档检查，24 张报告页的 222 个相对路径链接均有效。
原 PAF、q0–q3 与 LGZ 终版等 10 个文件的哈希及 mtime 不变。证据保留在 SSH 180 的
`~/cgat-reads-debug/post-lgz-flank-admission.rnZn4ccq/evidence/`，其中
`col0.check.json`、`col0-flank-verified.json` 和 `report-links.json` 分别记录交付、侧翼与报告检查。
